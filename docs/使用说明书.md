# slide2pdf 使用说明书

把**课件录屏视频**（老师全屏播 PPT，讲几秒翻一页那种）还原成 **PDF**。
两种工作模式：**静止换页检测**（默认，自动找"这一页停了多久"）和**固定间隔截帧**（每 N 帧 / 每 S 秒一张）。

产出是**位图 PDF**：像素与视频帧逐字节等价（零重编码），但不含可选文字。

---

## 1. 安装

工具本体是单文件 `tool/slide2pdf.py`，依赖只有两个：

| 依赖 | 用途 | 说明 |
|---|---|---|
| `ffmpeg` / `ffprobe` | 解码、抽帧、探测 | 必需 |
| `numpy` | 帧间差分统计 | 必需 |

不需要 PIL / OpenCV / PyTorch。

```bash
# 1) numpy（已有就跳过）
python3 -m venv venv && venv/bin/pip install numpy

# 2) ffmpeg：系统里没有就用静态版（无需 root）
curl -LO https://johnvansickle.com/ffmpeg/releases/ffmpeg-release-amd64-static.tar.xz
tar xf ffmpeg-release-amd64-static.tar.xz -C bin/

# 3) 工具会自动在 ./bin/*/ 下找 ffmpeg、ffprobe，也可以用 --ffmpeg/--ffprobe 显式指定
venv/bin/python tool/slide2pdf.py --help
```

找不到 ffmpeg 时的兜底顺序：`--ffmpeg` 参数 → `$FFMPEG` 环境变量 → `./bin/*/ffmpeg` → `PATH`
→ `pip install imageio-ffmpeg` 自带的那份。

**每个候选都会先做两次体检**：① 看文件头——Windows 上只认 `MZ`（.exe），Linux 上只认 `ELF`，
所以把 Linux 静态版 ffmpeg 拷到 Windows 旁边不会再去硬跑它；② 真跑一次 `ffmpeg -version` 冒烟测试。
两条都过了才用，否则跳过并给出中文提示（而不是 `OSError: [WinError 193]`）。

### Windows 上装 ffmpeg

```powershell
winget install Gyan.FFmpeg          # 装完新开一个终端，ffmpeg -version 能跑就行

# 或者免安装：
#   下 https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip
#   解压，把 bin\ffmpeg.exe 和 bin\ffprobe.exe 放到 slide2pdf.py 同目录（或 ./bin/ 下）

python slide2pdf.py "D:\Downloads\课件.mp4" --info     # 先验一下
```

`--info` 最后两行会打印它实际选中的 ffmpeg/ffprobe 路径，排查"到底用的哪个"很方便。

## 2.1 先扫描视频参数：`--info`

不生成 PDF，只报"这个视频是什么规格"（3~4 秒出结果）：

```bash
python tool/slide2pdf.py 课件.mp4 --info
python tool/slide2pdf.py 课件.mp4 --info --json          # 机器可读
python tool/slide2pdf.py 课件.mp4 --info --info-samples 5 # 抽 5 个窗口实测帧率
```

输出示例（本机那个 103 分钟的片子）：

```
文件      课件.mp4  (903.7 MB)
编码      h264  yuvj420p
分辨率    1920x1080   课件区（自动去黑边）1440x1080+240+0
帧率      标称 30 fps   平均 30 fps   → 恒定帧率(CFR)
实测      30 fps（3 个窗口抽测：1551.3s 起 2.0s 内 60 帧=30fps，…）
总帧数    186270（186270 ÷ 6209.152 s = 29.999 fps）
时长      01:43:29.2（6209.152 s）
码率      1.16 Mbps   time_base 1/90000
每帧间隔  33.3333 ms
```

判读要点：

- **标称(r_frame_rate) vs 平均(avg_frame_rate)**：两者相差 >0.01 就判为 **VFR（可变帧率）**，
  这种片子按"每 N 帧"截会得到不均匀的时间间隔；
- **实测**：在片子中间均匀取 K 个 2 秒窗口，逐帧读 `pts_time`，用 `(帧数-1)/(末pts-首pts)` 算真实帧率，
  不受容器元数据影响；
- **总帧数 ÷ 时长**：与标称对得上 = 没有丢帧/重复帧；
- JSON 输出字段：`r_fps/avg_fps/measured_fps/vfr/nb_frames/dur/crop/time_base/bit_rate/samples[]`。

## 3. 两种模式

### 3.1 静止换页检测（默认）

思路：录屏时一页课件会**静止停留**几秒到几分钟，切页/动画时画面才剧烈变化。

1. 全片按 `--scan-fps`（默认每秒 2 帧）解码成 80×60 灰度指纹；
2. 逐格统计"这一格多久变一次"，变化频率 > `--mask-anim`（35%）的格子视为常动区（内嵌动图、摄像头小窗、鼠标），**排除在比较之外**；
3. 剩余区域里，变化像素占比 > `--thr`（6%）的帧算"在变"，合并成转场区间；区间之间就是静止段；
4. 静止段时长 ≥ `--min-hold`（1.5 s）才当成一页；
5. 选帧：要求该帧对前后 ±1 s 也是静止（"干净帧"），且墨量不低于该段中位数，取最靠段中点的一帧；
6. 全分辨率抽帧 → 去重 → 合成 PDF。

### 3.2 固定间隔截帧（`--every` / `--every-sec`）

不做任何检测，按固定节奏截：

```bash
python tool/slide2pdf.py 课件.mp4 --every 150        # 每 150 帧一张（30fps = 每 5 秒）
python tool/slide2pdf.py 课件.mp4 --every-sec 30     # 每 30 秒一张
python tool/slide2pdf.py 课件.mp4 --every-sec 2 --start 00:19:00 --end 00:21:00
```

- 该模式默认**不去重**（你要的是"每 N 帧一张"，原样给），`--dedupe` 可打开；
- `--max-frames`（默认 500）防误操作：103 分钟 30fps 视频 `--every 30` 会算出 6000+ 帧，工具会直接拒绝并提示；
- 首页时间 = `--start`，之后每 `step/fps` 秒一页，CSV 里 `confidence=step`。

## 3.3 进度条

跑长视频要几分钟，跑的时候终端里会有一条原地刷新的进度条：

```
[1/3] 指纹扫描：80 x 60 @ 2 fps（每秒 2 帧）...
  解码扫描 [##########..............]  42.7% 128/300 剩 2s
  解码完成：300 帧（80 x 60 @ 2 fps）用时 3s
[2/3] 采样 300 帧 → 变化区间 1 个 → 静止段 2 个 → 页面候选 2 页
  抽帧 [############.............]  50.0% 1/2 剩 5s
  抽帧完成：2 张（1440x1080 PNG + 480x360 灰度副本）
[3/3] 页数：2（去重前 2）
已写出 out.pdf  0.2 MB  2 页  用时 10s
```

| 元素 | 含义 |
|---|---|
| `[###...]` | 进度条本体，格数按终端宽度自动定（6~26 格），只用 ASCII，Windows cmd 的 GBK 编码也不会乱码 |
| `42.7% 128/300` | 已完成比例 / 已处理量 ÷ 总量（解码阶段单位是帧）；上万自动缩写为 `24.8k` |
| `剩 2s` | 按当前速度估算的剩余时间；刚开始速度不稳时会跳一下，属正常 |
| `解码扫描` | 第一遍：全片解码成 80×60 小图，用来找"画面没变"的区间 |
| `抽帧` | 第二遍：只把选中的那几十帧按全分辨率解码成 PNG |

五条规则：

1. **默认只输出到终端**。`python x.py v.mp4 > log.txt` 或放到后台时自动静默
   （否则日志里全是 `\r` 刷新行，没法看）；想强制显示加 `--progress`，想彻底关掉加 `--no-progress`。
2. 进度条画在 **stderr**，PDF 路径等结果信息在 stdout，所以重定向 stdout 抓结果不会混进进度条。
3. 进度条跑完会把那一行擦掉，最终日志是干净的，适合贴到报告里。
4. **永远只占一行**：画之前先量终端列数，放不下就按固定优先级让路
   —— 额外信息 → 剩余时间 → 百分比小数位 → 标签截断 → 丢掉计数。
   中文标签按 **2 列** 计算（`unicodedata.east_asian_width`），
   所以窄窗口也不会因为中文被算成 1 列而折行。
5. 条长按"最坏情况"（100% + 最长剩余时间）一次定死，不会跑到一半突然变长。

## 3.4 输出目录与 PDF 合并

**输出到指定文件夹**（默认就放在视频旁边）：

```bash
# 默认：/path/to/课件.mp4 → /path/to/课件.pdf
python slide2pdf.py "/path/to/课件.mp4"

# 指定文件夹：/data/out/课件.pdf（目录不存在会自动创建）
python slide2pdf.py "/path/to/课件.mp4" --outdir /data/out

# 指定文件名：/data/out/第3讲.pdf
python slide2pdf.py "/path/to/课件.mp4" --outdir /data/out -o 第3讲.pdf

# 给绝对路径就等于忽略 --outdir
python slide2pdf.py "/path/to/课件.mp4" -o /data/other/第3讲.pdf
```

规则一句话：`-o` 带目录（或绝对路径）就按它走；只给文件名就落在 `--outdir`；
`--outdir` 不给就用视频所在文件夹。`--csv` / `--preview` 只给文件名时同样落进 `--outdir`。

**把几个 PDF 合并**（不重新编码，页图逐字节不变）：

```bash
# 默认用 pymupdf（装了就用，最快最稳）
python slide2pdf.py --merge 第1讲.pdf 第2讲.pdf 第3讲.pdf -o 合订本.pdf

# 没装 pymupdf 也能合：用内置实现（只支持传统 xref 表的 PDF，
# 本工具产出的 PDF 都支持；Chrome/qpdf 那种 xref 流会报错，装 pymupdf 即可）
python slide2pdf.py --merge a.pdf b.pdf --merge-raw -o merged.pdf
```

已实测：`work/tool_v5.pdf`（49 页）+ `课件还原.pdf`（52 页）→ 101 页 37.4 MB，
两种引擎渲染出来的每一页都与源文件**逐像素相同**。

## 4. 参数总表

### 视频参数扫描
| 参数 | 默认 | 说明 |
|---|---|---|
| `--info` | 关 | 只扫描视频参数（帧率/总帧数/时长/黑边），不出 PDF |
| `--info-samples K` | 3 | 实测帧率时取几个 2 秒窗口 |
| `--json` | 关 | 配合 `--info`，输出 JSON |

### 模式
| 参数 | 默认 | 说明 |
|---|---|---|
| `--every N` | 关 | 每 N **帧**截一张（固定间隔模式） |
| `--every-sec S` | 关 | 每 S **秒**截一张（固定间隔模式） |

### 时间范围（两种模式都生效）
| 参数 | 默认 | 说明 |
|---|---|---|
| `--start T` | 0 | 从这个时刻开始处理 |
| `--end T` | 片尾 | 处理到这个时刻为止 |

`T` 的写法都支持：`1140`、`19:00`、`00:19:00`、`00:19:00.5`、`19m`、`1h2m3s`。
输出 CSV 里的时间码是**视频绝对时间**（已自动加上 `--start`），可直接回视频定位。

### 静止检测（默认模式）
| 参数 | 默认 | 说明 |
|---|---|---|
| `--scan-fps S`（别名 `--fps`） | 2 | **每秒扫描多少帧**。2 = 每 0.5 s 一个采样点；想抓 1 秒级的快速切页就调到 4~5（耗时线性增加） |
| `--thr X` | 0.06 | 变化像素占比超过 X 就算"在变"。片子噪点大/有录像压缩杂讯时调高到 0.08~0.1 |
| `--min-hold S` | 1.5 | 静止多久才算一页。想抓"一闪而过的答案页"就调到 0.8 |
| `--mask-anim X` | 0.35 | 某格变化频率 > X 视为常动区域并屏蔽 |
| `--keep-motion` | 关 | 全程都在动的段（长动画）也取一帧，标记 `confidence=low` |
| `--keep-blank` | 关 | 保留"整页空白 / 纯黑"的段（默认丢弃，`ink<0.6%` 或 `>99%`） |
| `--extract-mode M` | auto | 抽帧方式：`auto`=先试 select 表达式，失败或表达式过长自动改逐帧 seek；`select`=只用表达式；`seek`=只用逐帧 seek |

### 输出与杂项
| 参数 | 默认 | 说明 |
|---|---|---|
| `-o/--out PATH` | 同名 .pdf | 输出 PDF：绝对/相对路径都行；**只给文件名时放进 `--outdir`**。父目录必须已存在（写错目录会**立刻**报错并提示最接近的现有目录） |
| `--outdir DIR` | 视频所在文件夹 | 输出目录（**不存在会自动创建**；不可写则退回当前目录） |
| `--dedupe` / `--no-dedupe` | 检测模式开、间隔模式关 | 重复页剔除开关 |
| `--max-frames N` | 500 | 固定间隔模式的帧数上限 |
| `--dpi N` | 150 | 页面尺寸 = 像素 × 72/N，只影响"物理大小"，不改变像素 |
| `--preview JPG` | 关 | 输出选页拼图（7 列缩略图），快速人工验收 |
| `--csv CSV` | 关 | 页码 ↔ 秒 ↔ 时间码 ↔ 停留时长 ↔ 墨量 ↔ 置信度 |
| `--dry-run` | 关 | 只分析不抽帧（检测模式会打印所有候选页和丢弃原因） |
| `--keep-temp` | 关 | 保留临时目录（里面是抽出的 PNG，可复用） |
| `--progress` / `--no-progress` | 自动 | 强制显示 / 关闭进度条（默认：终端里显示，重定向到文件时静默） |
| `--ffmpeg/--ffprobe PATH` | 自动 | 显式指定二进制 |
| `--merge PDF [PDF …]` | — | 合并模式：只把多个 PDF 按顺序拼成一个，不碰视频 |
| `--merge-raw` | 关 | 合并时用内置实现（不依赖 pymupdf；只支持传统 xref 表） |

## 5. 输出

| 文件 | 内容 |
|---|---|
| `xxx.pdf` | 每页一张 1440×1080 图（4:3 课件区，黑边已自动裁掉），页面 691.2×518.4 pt |
| `--csv` 表 | `page, t_sec, timecode, dwell_s, ink_pct, confidence, blank_risk` |
| `--preview` 图 | 所有选中页的 7 列缩略拼图，一眼看有没有垃圾页 |

CSV 字段：`dwell_s` = 该页在视频里停了多久；`ink_pct` = 非背景像素比例（太低=空白、太高=黑屏）；
`confidence=high` 干净帧 / `low` 动画段取帧 / `step` 固定间隔；`blank_risk=1` 表示墨量 < 2%（疑似空白页）。

---

## 6. 输出质量

- **无损**：抽出的 PNG 用 `-pred mixed` 压过（只影响体积），PDF 里直接复用 PNG 的 IDAT 数据块
  （`/FlateDecode` + `/Predictor 15`），**不做二次编码**。校验方式：把 PDF 按 `dpi=150` 渲染回来，
  与原 PNG 逐字节比对，`maxdelta = 0`。
- **不是矢量**：文字不可选、不可搜。要可搜需再叠一层 OCR 文本。
- **一页一态**：同一页的 PPT 动画/逐条出现的项目符号只保留一帧（默认是"最完整"的那一态）。

## 7. 性能（本机实测，103 分钟 1920×1080 视频）

| 阶段 | 耗时 |
|---|---|
| 黑边探测（3×15 s 采样） | ~15 s |
| 指纹扫描（2 fps，全片） | ~2.5 min |
| 全分辨率抽帧（~60 帧） | ~3.5 min |
| 合成 PDF | ~2 s |
| **合计** | **~6.5 min**（约 16 倍速） |

临时目录用 `tempfile`，结束自动删除；抽帧占空间约 `页数 × 0.5 MB`。

## 8. 常见问题

**Q: `OSError: [WinError 193] %1 不是有效的 Win32 应用程序`？**
工具找到了一个**不属于当前系统**的二进制（最常见：把 Linux 静态版 `bin/ffmpeg-7.0.2-amd64-static/ffmpeg`
和脚本放在了一起）。新版已经会给每个候选做"文件头（PE/ELF）+ `-version` 冒烟测试"两道体检并跳过不合适的，
找不到时直接给中文安装提示。处理办法：删掉 `bin/` 下 Linux 版的 ffmpeg/ffprobe，然后
`winget install Gyan.FFmpeg`，或把 Windows 版 `ffmpeg.exe`、`ffprobe.exe` 放到脚本同目录。

**Q: PDF 里出现"内容不全 / 被白块盖住"的页怎么办？**
这类页几乎都是**转场中间态**：擦除(wipe)、推入(push)、百叶窗、淡出到白——动画正好停在一半，
画面里有一大条纯白，静止时间又超过了 `--min-hold`，于是被当成一页。

工具现在的处理：

1. 抽帧后对每张候选算"最长空白带"（整条没有墨的行/列）；
   **竖向空白带 > 45%** 判为转场中间态，直接丢弃并打印 `丢弃 00:12:25.0 疑似转场中间态（竖白带 91%）`；
2. **横向空白带 > 55%** 只做提示、不丢弃——因为"标题栏 + 大面积空白"的正常页也长这样，
   宁可在 CSV 里标 `blank_risk=True` 让人复核，也不误删真页；
3. 不想丢就加 `--keep-wipe`，全部留下。

**Q: 抽帧失败，`Error initializing filters` / `Error : Cannot allocate memory`？**

这是"一次解码 + select 表达式"这条路的老毛病：候选页越多，表达式越长
（`between(n,7594,7594)+between(n,8024,8024)+…`）。实测 4 fps 扫描得到 132 个变化区间时，
表达式已有 2.6 KB 以上；某些 ffmpeg 构建（如 Windows 便携版 9.1）在初始化这种巨型滤镜图时直接 ENOMEM。

工具现在**自动兜底**：先按老办法试一次，一旦失败就清掉已抽的帧，改成**逐帧 seek**
（每帧起一个 ffmpeg 进程、用 `-ss` 定位，不拼表达式），并打印：

```
  ⚠ select 方式抽帧失败：...
  自动改用逐帧 seek 抽取（结果相同，只是每帧一个进程、慢一些）
```

也可以直接跳过尝试：`--extract-mode seek`。实测 25 分钟片段：select 48 s、seek 20 s；
静态页两者逐像素相同，动画/build 页可能差一个相邻亚态（1471 / 331776 字节），这本就是"某一瞬间"的差别。

**Q: 为什么不显示进度条 / 进度条刷屏？**
默认只在**终端**里显示（`sys.stderr.isatty()` 为真）。在 IDE 的"输出"面板、Jupyter、
`nohup ... > log` 这类场景下会静默。要强制显示：`--progress`；要彻底关闭：`--no-progress`。

**Q: 报错 `Unrecognized option 'vsync'` / `Error splitting the argument list: Option not found`？**

ffmpeg 各版本把"输出不补帧"这个开关改过三次名字：

| ffmpeg 版本 | 写法 |
|---|---|
| ≤ 4.x | `-vsync 0` |
| 5.1 ~ 8.x | `-fps_mode passthrough`（`-vsync` 变成废弃别名，会打警告） |
| 9.x 及以后 | 只剩 `-fps_mode passthrough`，`-vsync` 被彻底删除 |

工具会**自动按 `-fps_mode passthrough` → `-vsync 0` → `-vsync vfr` 的顺序降级**（`-pred mixed` 不认识也会自动退回默认预测器），所以正常不用管它。
三个都不认识时工具会**直接停下报错**，而不是硬着头皮抽帧——因为没有这个开关，ffmpeg 会按 30 fps 把同一帧复制成几百张，抽出来的帧和时间码全错。
这时换 ffmpeg 5.1+ 的版本，或用 `--ffmpeg` 指定完整路径。

**Q: 完全没有 ffprobe 行不行？**
可以。工具会退回用 `ffmpeg -i` 的 stderr 解析元数据（分辨率/帧率/时长/编码都能拿到），
只有"实测帧率"这一项拿不到（它需要逐帧读 pts）。`pip install imageio-ffmpeg` 只带 ffmpeg，
就属于这种情况；此时 `--info` 仍可用，`总帧数` 会显示为按时长×帧率估算。

**Q: 页数太多，同一页出现两三次？**
同一页的"逐步补内容"（build）会形成多个静止段。工具已把"只增不减"的相邻帧合并成最完整那帧
（`loss ≤ 2% 且 add > 0.5%`），但差异更大时仍会留下。可先 `--dry-run` 看候选和合并日志；仍多余就把
`--min-hold` 调大（如 3），或直接删掉 PDF 里那几页。

**Q: 出现空白页 / 一块白块盖住内容？**
那是视频里真实存在的画面：整页近白（讲课时清屏）、纯黑（"无信号接入"）、以及擦除/百叶窗/淡出到白这类
**动画中间态**在半途静止超过 `--min-hold` 秒。默认已经过滤（`ink<0.6%` 或 `>99%` 丢弃 + 干净帧要求），
想确认是哪一段就 `--dry-run` 看丢弃原因。

**Q: 漏页了（某页没被选中）？**
说明它在视频里停留 < `--min-hold` 秒，或全程在动。对策：`--min-hold 0.8`、`--scan-fps 4`、`--keep-motion`。

**Q: 选中的帧是转场残影（半透明/百叶窗）？**
调高 `--thr`（如 0.09）让转场被更早判定为"在变"，并保证 `--scan-fps ≥ 2`。

**Q: 时间对不上？**
用 `--csv` 的时间码回视频核对；注意 `-ss` 是**输入定位**，长片内的关键帧对齐可能有 ±1 帧误差。

**Q: 只想截一小段试试参数？**
`--start 00:19:00 --end 00:21:00`，1 分钟片 15 秒出结果。

**Q: 视频带鼠标/摄像头小窗？**
`--mask-anim` 会把高频变化的格子屏蔽掉（默认 35% 频率），鼠标在固定区域活动一般不会影响结果。

### 报 `FileNotFoundError: ... No such file or directory: 'D:\Downldoads\2.pdf'`

`-o` 的父目录不存在（多半是拼错，比如 `Downldoads` / `Downloads`）。工具现在会在**开始解码之前**
就检查输出路径并直接告诉你：

```
输出 PDF 的目录不存在：D:\Downldoads
  完整路径：D:\Downldoads\2.pdf
  是不是想写：D:\Downloads\2.pdf
  两种办法：① 用 --outdir 指定目录（不存在会自动创建） ② 自己先把该目录建好
```

推荐直接用 `--outdir`（省事，目录不存在会自动建）：

```bash
python slide2pdf.py "D:\Downloads\课件.mp4" --outdir D:\Downloads\out -o 2.pdf
```

顺带一提：`--start` 支持 `1h6m12s` / `1:06:12` / `66:12` / `3972` 四种写法，效果相同。

## 9. 内部流水线（想改代码看这里）

```
probe()             ffprobe 取 宽高/fps/时长
detect_crop()       3 个时间点 cropdetect 求众数 → 去黑边（本片 1440x1080+240+0）
fingerprint()       一次解码，crop+scan_fps+80x60 灰度 → rawvideo → np.memmap
analyse()           逐格变化频率→屏蔽常动格→chg[]→变化区间→静止段→干净帧→选帧→空白丢弃
extract()           一次解码，crop+scan_fps+select='between(n,a,b)+...'，split 双输出：
                      [o1] rgb24 PNG（入 PDF）   [o2] 480x360 灰度（去重用）
dedupe()            pair_metrics: chg / loss(墨→纸) / add(纸→墨)
                      loss≤2% & add>0.5%  → 同页补内容，换成更完整那帧
                      chg<3%，或 chg<10%&loss<8%&add<8% → 重复页，丢弃
build_pdf()         PNG IDAT → 图像 XObject（/FlateDecode + /Predictor 15），零重编码
```

对象号约定：`1` Catalog、`2` Pages、`3` Info、第 `i` 页 = `4+2i`、其图像 = `5+2i`、内容流 = `4+2n+i`。

## 9.5 稳定性与复现

- **抽帧是确定性的**：同一段视频、同一批帧号，两次跑出的 PNG 逐字节相同（`md5` 一致，实测过）。
- **页数会有 ±2~3 页的浮动**：去重靠"变化像素比例 / 内容减少 / 内容新增"三个启发式指标，
  处在阈值边缘的页（例如同一页的两个 build 中间态，`chg≈9~10%`）可能这一版合并、下一版保留。
  所以**不要用页数当验收标准**，用 `--preview` 拼图或直接翻 PDF 看。
- 想更稳：`--no-dedupe` 全留（页数会变多、但有重复），或调阈值自己控制。

## 10. 已知局限

- 无 OCR：文字不可选、不可搜；公式/符号想转文字要另接 OCR。
- 无矢量重建：不做背景色估计 + 文字重排，产物就是位图。
- 一页多态：动画/逐步显示只留一帧。
- 重复页判定靠像素统计，**没有 OCR 就没有真正的"页面身份"**：白色底、稀疏文字的页之间差异小，
  阈值调松会误删真页，调紧会留重复。默认值对"课件录屏"这类片子比较稳，特殊片子需要 `--dry-run` 校准。
- 视频里的鼠标点击、翻页动画、录屏水印会一起被"还原"进 PDF。
